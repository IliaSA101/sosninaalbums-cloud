### 1.1 Правило `site` и общий файл случаев

- **Факт.** `Owner` — `internal/config/config.go:65-71`; неизвестное поле в файле — ошибка (`dec.DisallowUnknownFields`,

- Новое поле `Site string \`json:"site"\``, **необязательное** (пусто — подпись текстом, как сейчас).
- Непустое значение принимается, только если верны **все** условия (005-4, 005-22):
  1. длина ≤ 200 байт; только печатный ASCII `0x21…0x7e` (пробел, таб, перевод строки, `\`, управляющие, не-ASCII —
     отказ; кириллический домен — только punycode `xn--…`);
  2. `url.Parse` без ошибки; `Scheme == "https"`; `Opaque == ""`; `User == nil`; `RawQuery == ""`, `!ForceQuery`;
     `Fragment == ""`; в `u.Host` нет `:` (порт и пустой порт `https://h.example:` — отказ, а М1);
  3. `Hostname()` — DNS-имя: метки `[a-z0-9]([a-z0-9-]{0,61}[a-z0-9])?` через точку, не меньше двух, без завершающей
     точки; **последняя метка начинается с буквы** — отсекает IP-литералы и числовые имена, которые WHATWG URL читает
     как IPv4 (`https://127.1`, `https://0x7f.1`, `https://0177.0.0.1` → `127.0.0.1`; прототип аудита, а М1);
  4. путь пуст или начинается с `/` и состоит из `[A-Za-z0-9._~/-]` и `%XX`; сегменты `.` и `..` (и `%2e` в любом
     регистре) — отказ: `URL()` их сворачивает (`/a/../b` → `/b`), и `href` разошёлся бы со значением (р2 Н-М6, а2 З4);
  5. канонический вид: `u.String() == s`.
- Один регэксп того же правила (для роли, 1.4):
  `^https://([a-z0-9]([a-z0-9-]{0,61}[a-z0-9])?\.)+[a-z]([a-z0-9-]{0,61}[a-z0-9])?(/([A-Za-z0-9._~/-]|%[0-9A-Fa-f]{2})*)?\Z`

  условие assert — нет сегмента `.`/`..`/`%2e` (`(^|/)(\.|%2[eE]){1,2}(/|$)` в пути — отказ).
- **Общий файл случаев** `internal/config/testdata/site_cases.json` — `[{"site": "…", "ok": true|false, "why": "…"}]`.
  Читают: `TestConfigOwnerSite` (Go) и статический тест роли `owners_rule_static.py` (регэксп из
  `roles/albums_svc/vars/main.yml` + сегменты + предел длины, как в assert); листалка — `studio.test.mjs` (правило
  браузера — §1.3). Расхождение трёх мест ловится тестом, а не простоем сервиса (р В9, а В5).
- Случаи (минимум): принять — `https://studio.example`, `https://studio.example/albums/2026`,
  `https://xn--80a.example`, `https://a-b.studio.example/%D0%B0`; отказ — `http://…`, `javascript:alert(1)`,

  `https:/\evil.example`, `https://h.example/a b`, `https://h.example/a/../b`, `https://h.example/./a`,
  `https://h.example/%2E%2e/a`, таб, `\n` в конце, `%zz`, 201 байт.

## 2. Листание колесом и тачпадом (листалка)

- **Факт.** Управление: кнопки и клавиши (`app.js:125-140, 165-167`), перетаскивание и свайп — StPageFlip 2.0.7
  (`book.js:48-64`, `swipeDistance: 30`, `mobileScrollSupport: false`). Слушателя `wheel` нет. Страница не
  прокручивается: `overflow: hidden` (`viewer.css:40, 57, 83`).
- Модуль `wheel.js` — машина состояний без DOM и часов, проверяется в node:

```
createWheel({ threshold, quiet, pagePx }) → { feed(ev, now) → 'next' | 'prev' | 'eat' | 'pass' }
ev: { deltaX, deltaY, deltaMode, ctrlKey, zoomed }
```

  - `ctrlKey` → `'pass'` (щипок тачпада Mac и Ctrl+колесо — масштаб браузера);
  - `zoomed` → `'pass'`: `app.js` подаёт `visualViewport && visualViewport.scale > 1` — при увеличении щипком два пальца
    двигают увеличенный вид, а не листают (а В6, доступность); если браузер даёт `1.0000x` без увеличения — порог
    `> 1.01` на усмотрение исполнителя (а2 З2);
  - `deltaMode`: 0 — пиксели; 1 — строки × 16; 2 — страницы × `pagePx` (высота сцены);
  - ось — бо́льшая по модулю из `deltaX`/`deltaY`; `+` — вперёд (колесо вниз; палец влево на тачпаде Mac с «естественной»
    прокруткой даёт `deltaX > 0`);
  - накопление по оси; `|acc| ≥ threshold` при снятом замке — `'next'`/`'prev'` и замок до тишины;
  - замок снимается после ≥ `quiet` мс без событий: инерция тачпада шлёт убывающие `delta` сотни миллисекунд — жест тот
    же; одна страница на жест; смена знака внутри жеста — копить заново, не листать до тишины;
  - всё, кроме `'pass'`, — `preventDefault()`.
- Стартовые значения (**гипотеза**): `threshold = 40` px, `quiet = 450` мс. Chrome под Windows — 100 px на щелчок,
  Firefox — `deltaMode 1`, 3 строки (48 px): щелчок = страница (**факт** по документации браузеров).
- `app.js`: `document.addEventListener('wheel', onWheel, { passive: false })`; без `state.book` — ничего. `preventDefault`
  гасит переход «назад/вперёд по истории» свайпом на Mac в Chrome (**факт**; Safari — **гипотеза**). Плюс
  `overscroll-behavior: none` у `html, body`.
- Что `flipNext` во время анимации игнорируется — **гипотеза** (браузер стенда); итог жеста не меняет — замок держит.
- Телефон: `wheel` нет, касания — в StPageFlip.
- **Где проверяется (р В10, 005-27).** До выпуска: `wheel.test.mjs` (`node --test`) и браузер стенда на рабочей ВМ
  (Linux: мышь, `WheelEvent` из консоли разработчика с инерционной серией). Mac (тачпад, Safari и Chrome) к стенду на
  `127.0.0.1` рабочей ВМ не подключить — проверка владельцем после раскатки v0.1.2 на демо-альбоме сервера. Пороги —
  константы модуля; если жест «не тот» — правка констант следующим выпуском (v0.1.3). Без тачпада вперёд-назад листают
  кнопки и клавиши, как в v0.1.1, — регрессии нет.

## 4. Раскатка (инфраструктура)

### 4.1 Привязка адреса CLO и защита от удаления сервера

- **Факт** (провайдер `clo-ru/clo` 2.8.0, `resource_ip_attach.go`): `is_primary` — `Optional + Computed`, не `ForceNew`;

  до `SetId`: адрес привязан в API, в state привязки нет, отката нет. `Importer` нет; `Read` на «не найден» — ошибка.
- **Факт** (design 002 §3, `002-provisioning/design.md:251-255`): удаление сервера передаёт его адреса в запрос
  удаления; спасает только привязка в state, которую tofu снимает раньше сервера.
- **Факт** (`deploy/tofu/clo/tofu-entry.sh`): без файла токена пропускает только `init | show | output | fmt | version`;
  точку входа задаёт только код (`provision.sh:367`). Поэтому сверка state — `show -json`, а не `state list` (р В1).
- **Следствие:** пока привязки нет в state, **любой** план с удалением сервера — `--replace-server` или пересоздание
  из-за поля `ForceNew` (имя, размер, новая схема провайдера; `ignore_changes` — только три поля, `main.tf:52`) —
  удалит публичный адрес (а В4).
- Правки:
  1. `deploy/tofu/clo/main.tf:61` — строку `is_primary` убрать, комментарий «почему» над ресурсом.
  2. `deploy/tests/provision/tofu_static.py:216` — якорь случая «провижинер» — на `entity_id   = clo_compute_instance.srv.id`;
     новый отрицательный случай «`is_primary` в привязке».

     **Проверка плана падает закрыто** (а2 Н2) — отказ (код 3) при любом из:

### 4.3 LLMNR, mDNS и слушатели в `configure`

- **Факт** (прототип: Debian 13.7, пакет `systemd-resolved`, Podman `--systemd=always` с возможностями цели стенда,
  `deploy/tests/provision/run.sh:174`): `systemd-resolve` слушает tcp/udp 5355 на `0.0.0.0` и `[::]`. Без `SYS_ADMIN`
  служба не стартует (217/USER) — у цели стенда он есть. Drop-in `[Resolve] LLMNR=no MulticastDNS=no` + перезапуск →
  остаются `127.0.0.53%lo:53` и `127.0.0.54:53`; `resolvectl status`: `Protocols: -LLMNR -mDNS …`.
- Drop-in — `/etc/systemd/resolved.conf.d/99-sa.conf`: файлы `resolved.conf.d` из `/etc`, `/run`, `/usr/lib` сортируются
  по имени, **побеждает последний** — `00-` перекрыл бы любой файл пакета или cloud-init (р М10, а М4). У sshd наоборот
  (первое значение) — там `00-sa.conf` верно; «почему» — в комментарии шаблона.
- Роль `bootstrap` (идёт и в `site.yml:20`, то есть в каждом `configure`): задачи `resolved.yml` — drop-in (0644, root);
  перезапуск — задачей при `changed` (или обработчик + `meta: flush_handlers`, образец — `roles/nftables/tasks/main.yml:31`;
  своих `handlers/` у роли нет) **до** самопроверки, иначе первый `configure` увидит старое состояние (р2 Н-М5). Служба
  активна — самопроверка `LC_ALL=C resolvectl status`: строк `Protocols:` **не меньше одной** (иначе отказ — сменился
  формат вывода), и в каждой (глобальная и каждая связь) `-LLMNR` и `-mDNS` (а2 Н5); служба не установлена — пропуск.
  Тег `verify_resolved` в `verify.yml`.
- **Слушатели в `configure`** (р В4): `verify.yml` зовут только стенды (`tests/provision/verify.sh`, `full.sh:254`),
  `site.yml:30-35` в `post_tasks` проверяет лишь `verify_admin.yml` — потому 5355 на сервере прошёл `configure` молча.
  Проверку слушателей (`roles/nftables/tasks/verify.yml:56-84`) вынести в `listeners.yml` (её же включает `verify.yml`) и
  добавить в `post_tasks` `site.yml`. **Риск:** имя процесса DHCP-клиента образа CLO в списке (`verify.yml:80`) —
  **гипотеза**; провал — в конце `configure`, после изменений. Поэтому до выпуска владелец снимает `ss -Htulpn` на
  сервере (README §5.7) и сверяет по правилу: `127.*`/`::1` — любые; tcp 22 — `sshd`; tcp 80/443 — `caddy`; udp 68/546 —
  процесс из списка `verify.yml:80`; иное — правка списка в этой же пачке. Слушатели rootless Podman сервиса уже
  проверяет полный стенд CI (`full.sh:254-255`).
- **Ложный провал проверки слушателей** (р2 Н-М8): `site.yml` падает до записи `deployed-image`, `deployed-commit` и
  `install_libexec` (`provision.sh:291-295`) — новый образ уже запущен, а учёт раскатки прежний. Восстановление (README):
  правка списка в коде → bundle → `review.sh` → `configure` (тот же образ, проверка проходит, учёт пишется). До этого
  порог отката — прежняя раскатанная версия; откатываться не нужно — сервис работает, порты закрыты nftables.
- Стенд: пакет `systemd-resolved` в `deploy/tests/provision/target.Containerfile`. Что пакет не ломает DNS цели

## 5. Дымовая проверка и список альбомов (инфраструктура)

Редакция 3 (а2 Н1, Н4; р2 Н-М7): боевые запуски и выпуск их токенов — **только на ops-ВМ** под `sa-ops`; на рабочей ВМ —
только стенд со своими токенами. Почему: секреты, inventory и копии живут только в доме `sa-ops` (`deploy/README.md:117-118`,
ВР-1: рабочая ВМ отдана агентам). Токен `ops-ls` на сервере может всё в учётной записи фотографа, а «только `GET`» —
свойство клиента, который на рабочей ВМ был бы под контролем агента.

### 5.1 Код

- **Факт** (а В1): `deploy/tests/access/sa.py:20-28` при импорте читает из окружения токены, базу и CA стенда (р2 Н-М9);
  `sa_api.py:97` записывает id в `/out/secrets.txt`. `smoke.py` их не импортирует.
- `deploy/ops/smoke.py` — **только стандартная библиотека Python** (`http.client`, `ssl.create_default_context`, `json`,
  `secrets`): идёт и в контейнере контроллера ops-ВМ (образ на `python` по дайджесту, `deploy/ansible/Containerfile:10`;
  что в нём есть `ca-certificates` — **гипотеза**, проверить в пачке), и в образе стенда; pip и `httpx` не нужны.
  Однотонный JPEG — константа base64 в самом `smoke.py` (как `sa_api.py:22-35`, с солью в `COM`); `sa_api` не трогается.
  - токен — **только** из `/run/sa/token` (том ro; срезать перевод строки), не из окружения и не из `argv`;
  - база — `https://<домен>`: на ops-ВМ — из `SA_DOMAIN` (`provision.env`), аргументом не задаётся (опечатка не отправит
    токен чужому серверу; а2 Н4); на стенде — домен стенда из `stand.sh`;
  - CA — системное хранилище; на стенде — корень `tls internal` (путь задаёт только `stand.sh`);
  - редиректы не выполняются (3xx — провал шага); запись файлов и журнал (`logging`) не включаются (а2 З1);
  - главный обработчик ловит `BaseException`, печатает **номер шага и имя класса исключения**, без `str(e)` (а В2); из
    тела отказа — только поле `error` (короткий код контракта); вывод — номер шага, код ответа, итог; токен, id, ссылка
    и пароль `PATCH` (`secrets.token_urlsafe`) не печатаются.
- Команды:
  - `upload` — сначала `GET /v1/albums`: список не пуст → отказ без `POST` (а В3). Дальше: `POST` (4 однотонные страницы,
    название `smoke`, **`expires_at` = сейчас + 1 час**: срок задаёт клиент — `internal/api/body.go:112`, предела срока у
    владельца нет — `config.go:65-71`; короткий срок ограничивает остаток при сбое) → `PUT` страниц → `publish` →
    `GET /a/<id>/` 200, `manifest.json` 200, картинка 200 `image/jpeg` → `PATCH` пароль → `manifest.json` 401 → `DELETE`
    → `/a/<id>/` 404. Уборка — `DELETE` **только id этого прогона** в `finally`.
  - `clean` — остаток после сбоя: `GET /v1/albums`; **все** элементы с названием `smoke`, их не больше двух и у каждого
    `expires_at` не позже «сейчас + 2 часа» → `DELETE` каждого; иначе отказ без удалений (признак «не токен `smoke` или
    альбом не наш»; р В8). Без `clean` остаток уходит сам по сроку.

    по `Retry-After` (р М12); итог — число и сумма. Названия — ПД фотографа, только на экран терминала ops-ВМ.
