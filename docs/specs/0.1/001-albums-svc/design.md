# 001. Сервис листалок MVP — техрешение

Основной файл — [../001-albums-svc.md](../001-albums-svc.md); развилки — [../decisions.md](../decisions.md),
раздел «спека 001» (001-1…001-22). Контракт `/v1` — спека 146 программы (design §2.2, §2.3, §6) и модуль
`api/albums` (`v1/openapi.yaml`, README «Соглашения вне /v1»): здесь только то, что решает сервис.
Решение по стеку — см. приватные заметки («решение §N»). Пометки: **(факт)** — проверено кодом,
документацией, `go doc` или прототипом; **(гипотеза)** — проверить в указанной задаче.

## 1. Схема запросов (001-2)

```
программа ──HTTPS /v1/*────────► Caddy ──reverse_proxy (unix-сокет)──► albums-svc
клиент ────HTTPS /a/<id>/…─────► Caddy ──reverse_proxy (unix-сокет)──► albums-svc
клиент ────HTTPS /viewer/*─────► Caddy ──reverse_proxy (unix-сокет)──► albums-svc (листалка в бинарнике)
```

- **Всё отдаёт сервис.** Caddy — TLS, `reverse_proxy`, заголовки своих ответов, журнал; к `data/` доступа
  не имеет. На каждый запрос `/a/<id>/…`: индекс → опубликован и `now < expires` → вход (если пароль) →
  имя файла есть в `published` → `http.ServeContent` с `type` из манифеста. Один обработчик `/v1` + `/a/`
  проходит весь `Conformance` на `httptest` за ~1 с **(факт: прототип второго мнения)**.
- **Листалка** (`web/viewer/`) встроена в бинарник через `embed`; файлы отдаются из каталога
  `/viewer/<версия>/…`, версия — 8 hex sha256 всех встроенных файлов (`viewer.Version()`, считается один раз
  при старте; чужая версия — 404), поэтому `Cache-Control: immutable` честный, шага сборки нет,
  относительные импорты модулей работают как есть (001-28). Страница «Альбом не найден» —
  `web/viewer/notfound.html` без стилей и ссылок (Caddy отдаёт её и при 502, когда `/viewer/` недоступен),
  один источник для сервиса и `handle_errors` Caddy (развёртывание копирует тот же файл).
- **Сеть.** Сервис слушает unix-сокет в каталоге, общем с Caddy (сокет 0660, группа Caddy), контейнер —
  `Network=none`: нет TCP-порта для соседей по машине, некому подделать `X-Sa-Client-IP`. Запасной путь —
  TCP на loopback с `trusted_proxy` в конфиге (если сокет из rootless-контейнера не сложится — И1,
  **гипотеза**). Проверка здоровья в Quadlet — `albums-svc health` по сокету изнутри контейнера.
- **Caddy**: до проксирования срезает входящие `X-Sa-*`, `X-Forwarded-*`, ставит
  `header_up X-Sa-Client-IP {remote_host}`; `request_body max_size` — 16 МБ для `/v1/*`, 4 КБ для
  `POST /a/*/login`, 1 КБ прочим; тайм-ауты сервера: `read_header` 10 с, `read_body` и `write` 600 с (не
  меньше наибольшего срока чтения страницы у сервиса — 540 с, §4), `idle` 2 мин; прочие пути — 404. Свои
  ответы (404 вне маршрутов, 502 при остановленном сервисе) — `handle_errors` с `notfound.html` и
  заголовками §5.6; HSTS. Образ — по дайджесту.

## 2. Данные на диске (необратимо — второе мнение)

Все операции — через `os.Root` (`Rename`, `MkdirAll`, `RemoveAll`, `OpenFile` в Go 1.27 — **факт: `go doc
os.Root`**). Пишет один процесс: `flock` на `data/LOCK`; второй экземпляр не стартует. Замок — на отдельном файле:
`LAYOUT` переписывается через `rename`, новый inode снял бы замок (001-27).

```
data/                               0700, том контейнера (вне домашнего каталога хоста)
  LOCK                              0600  пустой, только flock
  LAYOUT                            {"layout": 1, "last_seen": "…", "clock_hold": null}
  owners/<slug>/albums/<id>/        0700  slug — из конфига, ^[a-z0-9][a-z0-9-]{0,31}$
    meta.json                       0600  источник правды об альбоме
    <sha256>.jpg                    0600  страницы по хэшу; имя = поле file манифеста
  tmp/                              0700  .part приёма и атомарной записи (тот же раздел)
  trash/                            0700  удаляемые каталоги альбомов, <id>.<rand>
  quarantine/                       0700  каталоги с негодной meta, <id>.<rand>; разбор вручную (runbook:
                                          сервис его не убирает и в запасе места не считает)
```

- **Каталог на владельца** (решение владельца 31.10, п. 1): второй фотограф — запись в конфиге; `slug` в
  адрес не входит, индекс id → альбом общий для всех владельцев.
- **Страницы по хэшу внутри альбома** (001-3): неизменённые страницы новой редакции не грузятся заново,
  удаление альбома — один каталог.
- **Атомарная запись** `store.writeAtomic`: `tmp/<crypto/rand>.part` с `O_CREATE|O_EXCL`, 0600 → запись →
  `Sync` → `Rename` → `Sync` каталога. Сначала диск, потом индекс.
- **Уборка мусора** (001-23). **При старте**, до приёма запросов, — всё: `tmp/*`, `trash/*`, каталоги
  альбомов без `meta.json`. **В работе**, каждые 5 минут, — только `tmp/*` с mtime старше 600 с (дольше
  любого запроса, §4: идущий `PUT` и чужой `writeAtomic` не режутся), `trash/*` и каталог альбома без
  `meta.json` — под мьютексом этого альбома, только если id нет в индексе и mtime каталога старше 600 с
  (окно между `MkdirAll` и записью `meta` в `POST`). Неразбираемый `meta.json` не удаляется — в
  `quarantine/` (§2.1). Сироты не воскресают: `MkdirAll` есть только в `POST /v1/albums` (**факт:
  прототип — `MkdirAll` в пути страницы воскрешал каталог удалённого альбома**).
- **Корзина**: удаление альбома — `Rename` каталога в `trash/<id>.<rand>`; `RemoveAll` внутри `trash/` —
  одна функция `store.purgeTrash`, её зовут и удаление, и уборка.
- `RemoveAll` не затирает блоки на диске; затирание — не цель MVP (принято, 001-21).

### 2.1 `meta.json`, формат 1 (001-14)

```json
{
  "format": 1, "id": "…26 знаков…", "owner": "p1",
  "created": "…", "updated": "…", "expires": "…",
  "published": {"at": "…", "manifest": {"…": "albums.Manifest, file заполнены сервисом"}},
  "draft":     {"at": "…", "manifest": {"…": "та же форма"}},
  "password":  {"alg": "hmac-sha256", "key": "pw/1", "salt": "<base64url 16 Б>", "hash": "<base64url>"},
  "epoch": 0
}
```

- `published`, `draft`, `password` — `null`, если нет. Ссылка, открытый пароль, IP не хранятся; `url`
  строится из `public_base`.
- **Неизвестные поля сохраняются** при перезаписи (`json.RawMessage`): откат образа не теряет поля новой
  версии (**факт: прототип — без этого старая версия их стирала**).
- `format` новее своего — **отказ старта**, не чистка (откат `podman auto-update`).
- `meta.json` не разбирается или `id`/`owner` не совпали с путём — каталог в `quarantine/<id>.<rand>`,
  строка в журнал, не удаление (страницы целы для разбора).

## 3. Альбом: жизненный цикл

| Действие | Под мьютексом альбома |
|---|---|
| `POST /v1/albums` | id → `MkdirAll` каталога → `meta` → индекс |
| `PUT …/pages/{n}` | только финал: повторная проверка → `Rename` `.part` в `<sha>.<ext>` |
| `PUT /v1/albums/{id}` | `meta.draft` ← новая; удалить файлы вне `published` ∪ новой `draft` |
| `publish` | `meta`: published ← draft, draft ← null; удалить файлы, которых нет в новой `published` |
| `PATCH` | `meta`: срок; пароль (новая соль); `epoch++` при `revoke_sessions` |
| `DELETE`, срок, сутки | индекс → `Rename` каталога в `trash/<id>.<rand>` → `store.purgeTrash` |

- **id** (001-15): 26 знаков base32 строчными (`a–z2–7`), 130 бит; каждый знак — байт `crypto/rand` & 31
  (`crypto/rand.Text` не берём: его длина может вырасти — **факт: `go doc`**). Проходит
  `albums.CheckID` (22…64 знака `[A-Za-z0-9_-]`, первый не `-` — **факт: `check.go`**). Совпадение с
  индексом — новый розыгрыш.
- **Порядок блокировок**: сначала мьютекс альбома (`sync.RWMutex`, отдача `/a/` — чтение), затем коротко
  запись в индекс.
- **Гонки** (`PUT` страницы ↔ `DELETE`, уборка, `PUT` альбома): тело страницы читается без блокировки в
  `tmp/`; финал — под мьютексом с повторной проверкой «альбом в индексе, срок не истёк, `sha` есть в
  `published` ∪ `draft`», иначе `.part` удаляется и ответ `404`/`409`.
- **Текущая редакция** — `draft`, если есть, иначе `published`. `missing` — номера небелых страниц текущей
  редакции без файла. `publish` без всех файлов — `409 pages_missing`; повторный без правки — `200`.
- **`draft.at`** — время первой неопубликованной правки; замена `draft` его не обновляет (иначе правку
  можно держать вечно). `draft` старше 24 ч отбрасывается уборкой вместе со своими файлами; ни разу не
  опубликованный альбом старше 24 ч от `created` удаляется. Программа на следующей выгрузке начинает с
  `PUT /v1/albums/{id}` (design 146 §3.3 п. 5 — **факт**).
- **Срок**: `expires` зажимается к `now + max_days` (366, 001-12; в модуле по умолчанию 365). Доступ — 404
  по времени запроса, физическое удаление — уборка.
- **Сторож часов** (001-19): пауза ставится, если при старте `now − last_seen > 30 дней` или
  `now < last_seen`, либо в работе настенные часы разошлись с монотонными больше чем на 10 минут в любую
  сторону. Пауза пишется в `LAYOUT.clock_hold` (причина, время) и переживает перезапуск и `auto-update`;
  пока она стоит, `last_seen` не двигается и не идёт **ни одно удаление по времени** (срок, неопубликованный
  альбом и `draft` старше суток); доступ всё равно 404 по времени запроса. Снять — разовый запуск
  `albums-svc -clock-ok -data <dir>` по runbook: при остановленном сервисе, под flock, чистит `clock_hold`,
  ставит `last_seen` ← now и выходит; в юнит Quadlet флаг не пишется. Вне паузы `last_seen` пишется
  каждым проходом уборки.
- **Неполный альбом** (восстановление, сбой диска): у опубликованного нет хотя бы одного файла `published`
  — 404 на всех `/a/<id>/…`, пока его не опубликуют заново; `/v1` им управляет как обычно. Проверка — при
  старте и при отдаче: под `RLock` альбома имя ищется в **текущей** `published` и открывается fd, отдача —
  из fd после снятия блокировки. `ENOENT` у файла текущей редакции — пометка «неполный» и строка журнала;
  имени нет в текущей `published` (клиент со старым манифестом после `publish`) — 404 только этому файлу.

## 4. Приём `/v1`

- **Пути**: неканонический путь (`%2e`, `..`, `//`, регистр `/V1`) — `404` до маршрутизатора, а не `301`
  `ServeMux`.
- **Токен**: `Authorization: Bearer <t>`, `albums.CheckToken`; в конфиге — `sha256(t)` hex; сравнение
  `subtle.ConstantTimeCompare` со **всеми** записями без раннего выхода. Нет, чужой, плохой вид, не
  `Bearer`, токен в строке запроса — одинаковый `401`. Владелец альбома — фотограф, не токен; альбом
  другого владельца — `404`.
- **id в пути** `/v1/albums/{id}…` проверяется после токена: вне `^[a-z2-7]{26}$` — `404 not_found` с тем же
  телом, что у несуществующего (**факт: `Conformance` шлёт `"Zz"+24×q` и ждёт `404 not_found`, а `a×22`
  без токена — `401`**).
- **JSON**: `MaxBytesReader(1 МБ)` → `413`; ровно один объект. Свой подсчёт числа страниц и суммы `bytes`
  → `413` (К1), затем `ValidateCreate`/`Validate`/`ValidatePatch` → `400 bad_manifest`; пишется повторная
  сериализация типа, `file` ставит сервис. Страница `image/webp` в 0.1 — `400 bad_manifest` (`accept_webp:
  false`, 001-6, К6).
- **Квота** (001-11): `quota_bytes` (байты различных файлов `published` ∪ `draft` всех альбомов
  владельца), `max_albums`, `disk_reserve_bytes` — на `POST`/`PUT` альбома **и** на `PUT` страницы до
  чтения тела (`свободно − Content-Length ≥ reserve`); превышение — `413` (К2).
- **Страница** `PUT /v1/albums/{id}/pages/{n}`, порядок: токен → id по индексу (нет, чужой, истёк — `404`)
  → слот загрузки (не больше 8 активных на владельца, иначе `429`, `Retry-After: 5`) → `ParsePageN(n, K)`,
  белая страница — `400 bad_page` → `Content-Type` ≠ `type` — `400 bad_page` → `Content-Length` > `page_bytes`
  — `413`; известен и ≠ `bytes` — `409 hash_mismatch` (оба до чтения); нет (`-1`, chunked) — допускается,
  счёт идёт от `bytes` → квота и запас (от `bytes`) → тело всегда через `MaxBytesReader(bytes)` в `.part`
  с подсчётом `sha256` → байт меньше или больше `bytes`, хэш не тот — `409 hash_mismatch` → сигнатура
  `FF D8 FF` — `400 bad_page` → маркеры до SOS по белому списку: APP0 (JFIF), APP2 (ICC), APP14 (Adobe),
  COM, DQT, DHT, SOFn, DRI; прочие (APP1 Exif/XMP, APP13 IPTC, APP11 …) — `400 bad_page` (К5). COM
  разрешён: программа пишет в него свою метку (**факт: `internal/export/web_test.go` программы**), образцы
  `Conformance` тоже. Разметка идёт до EOI: после SOS между сканами только DHT/DQT/DRI/COM, сканов
  ≤ 64, хвост после EOI ≤ 16 байт 0x00/0xFF (MPO и полиглоты — отказ); APP0 только `JFIF\0`, APP2 только
  `ICC_PROFILE\0`. Принятый остаток: внутри данных скана, ICC, JFIF и COM могут лежать произвольные байты —
  их не прочтёт ни один разборщик Exif/GPS, а закрыть это можно только декодированием → размеры `image/jpeg.DecodeConfig` ≠ `w`/`h` — `400 bad_page` → финал под
  мьютексом (§3) → `204`. Файл уже есть — `.part` удаляется.
- **`http.Server`**: `ReadHeaderTimeout` 10 с, `IdleTimeout` 120 с, `MaxHeaderBytes` 16 КБ, `ReadTimeout`
  30 с; для `PUT` страницы — `ResponseController.SetReadDeadline` на `60 с + bytes / 32 КБ/с` (≤ 540 с
  при 15 МБ) (зеркало клиента, design 146 §2.4); `ErrorLog` — через `logx`.
- **`GET /v1/albums`**: альбомы владельца без истёкших; `title`, `pages` — из `published`, иначе из `draft`;
  `published` — есть ли опубликованная редакция; `has_password` — из `meta`.
- **`GET /v1/health`**: `{api:"v1", limits}` без токена.
- Ошибки — `{"error":{"code","message"}}`, `message` без значений полей; пароль нет ни в одном ответе.

## 5. Просмотр, пароль, cookie (необратимо — второе мнение)

### 5.1 `/a/<id>/…`

1. Метод не `GET`/`HEAD` (кроме `POST /a/<id>/login`) — `404`.
2. Путь строго `^/a/([a-z2-7]{26})/(|manifest\.json|view\.json|[0-9a-f]{64}\.jpg)$`, без `%`, строка
   запроса игнорируется; иначе `404`. `/a/<id>` без слэша — `308` на `/a/<id>/` только для существующего
   опубликованного альбома (иначе `404`).
3. id в индексе, опубликован, полон (§3), `now < expires`; файл — только из `published`. Иначе `404`.
4. Пароль есть, годной cookie нет — `401`: для `/a/<id>/` — форма входа, для прочих — пустое тело.
5. `/a/<id>/` — HTML листалки без ПД: `<title>Альбом · <студия></title>`, название рисует скрипт из
   `manifest.json`; `view.json` — `{"studio": "…"}` из конфига.

Все `404` — одно тело (`notfound.html`, §1) и одинаковые заголовки у сервиса и в `handle_errors` Caddy.

### 5.2 Вход `POST /a/<id>/login` (001-17)

- Форма ≤ 4 КБ, поле `password`; альбом нет, не опубликован или истёк — `404`.
- **Лимит попыток атомарно**: проверка и учёт — в одной критической секции, попытка засчитывается до
  сверки; успех возвращает её и сбрасывает ключ «альбом+IP». Превышение — `429` + `Retry-After` + форма.
- Нет `X-Sa-Client-IP` или запрос не от доверенного пира (TCP-вариант) — `503` и строка журнала, а не
  общий ключ для всех.
- Пустой пароль и ошибка формата (`CheckPassword`) — неверный пароль: засчитывается, тот же `401`.
- Верно — `303` на `/a/<id>/` + cookie; неверно — `401` + форма «Неверный пароль», cookie нет.
- Поле формы: `autocomplete="current-password" autocapitalize="none" autocorrect="off" spellcheck="false"`.

### 5.3 Пароль (001-5)

`hash = HMAC-SHA256(k_pw, salt ‖ id ‖ NFC(TrimSpace(p)))`; `salt` — 16 Б `crypto/rand` на альбом,
**новая при каждой смене пароля**: старые входы умирают сами, потому что соль входит в подпись cookie
(строже контракта, программе не мешает — К7). При установке — `CheckPassword`, затем обрезка; после неё
меньше 4 знаков — `400 bad_manifest`. NFC — `golang.org/x/text/unicode/norm` (новая зависимость, Т0).
Сравнение `hmac.Equal`. Медленный KDF не нужен: без секрета офлайн-перебор невозможен (решение §5).

### 5.4 Cookie (001-4)

- Имя `__Secure-sa_session`; `Path=/a/<id>/`, `Secure`, `HttpOnly`, `SameSite=Lax`, без `Domain`,
  `Max-Age = min(30 дней, до expires)`.
- Значение `1.<epoch>.<exp>.<mac>`, `mac = base64url(HMAC-SHA256(k_cookie, "1|" id "|" salt "|" epoch "|"
  exp))`. Проверка: строгий разбор `epoch` и `exp` (десятичные без знака и ведущих нулей), `exp > now`,
  затем сервер **строит строку заново** из `epoch` и `salt` из `meta` и сравнивает целиком за постоянное
  время — без нестрогого декодирования base64 (**факт: прототип — нестрогий разбор давал ~6 % подделок с
  теми же байтами**).
- Перебираются все cookie с этим именем (`r.CookiesNamed`, не больше 4); годна хоть одна (**факт:
  `r.Cookie` берёт только первую**).
- `revoke_sessions` → `epoch++`; смена пароля — новая соль; оба делают прежние cookie негодными.

### 5.5 Лимит попыток (стартовые значения, конфиг)

| Ключ | Предел |
|---|---|
| альбом + IP | 5 неудач / 15 мин |
| IP | 20 неудач / час |
| альбом | 20 неудач / 24 ч |

IPv6 — по /64 после `netip.Addr.Unmap()` (`::ffff:a.b.c.d` — это IPv4). Оценка (расчёт): 20 × 366 ≈ 7300
попыток против ≈ 2·10⁶ паролей «Придумать» — < 0,4 % за год. Ключи «альбом» не вытесняются (их не больше
альбомов), ключей с IP — не больше 50 000, вытесняется старейший. В памяти; после перезапуска — с нуля.

### 5.6 Заголовки

Все ответы `/a/`: `X-Robots-Tag: noindex, nofollow`, `Referrer-Policy: no-referrer`,
`X-Content-Type-Options: nosniff`, `Cross-Origin-Resource-Policy: same-origin`, `X-Frame-Options: DENY`.
HTML листалки и формы — `Content-Security-Policy: default-src 'none'; script-src <public_base>/viewer/;
style-src <public_base>/viewer/; img-src 'self'; connect-src 'self'; base-uri 'none'; form-action 'self';
frame-ancestors 'none'`; картинки — `default-src 'none'; sandbox`. Кэш: форма, `401`, `404`, `429` —
`no-store`; страница, `manifest.json`, `view.json` — `private, no-cache`; картинки — `private,
max-age=86400, immutable` (держатся у клиента и после отзыва — принято, 001-21). Нет `og:image`.
Листалка не добавляет строку запроса к `manifest.json`.

## 6. Конфиг и секрет (001-9, 001-10, 001-16)

```json
{
  "listen": "unix:/run/albums-svc/http.sock",
  "trusted_proxy": "",
  "public_base": "https://albums.example.org",
  "data_dir": "/data",
  "secret_file": "/run/secrets/albums_master",
  "limits": {"page_bytes": 15728640, "pages": 300, "album_bytes": 1073741824, "title_len": 200, "max_days": 366},
  "accept_webp": false,
  "unpublished_ttl": "24h",
  "disk_reserve_bytes": 2147483648,
  "login": {"per_album_ip": "5/15m", "per_ip": "20/1h", "per_album": "20/24h"},
  "owners": [
    {"slug": "p1", "studio": "Студия …", "quota_bytes": 10737418240, "max_albums": 500,
     "tokens": [{"name": "ноутбук", "sha256": "<hex>"}]}
  ]
}
```

- Домен — только `public_base`, из приватного inventory. Проверка при старте, ошибка — выход ≠ 0 без
  значений секретов: `public_base` — `https://` (http — только loopback-стенд) без пути, запроса,
  пользователя; `listen` — `unix:` или loopback `tcp:` (тогда `trusted_proxy` обязателен); `slug`
  уникальны и по шаблону; `studio` 1…100 знаков без управляющих; `sha256` уникальны среди всех владельцев.
- **Секрет** (необратимо): файл — base64url не меньше 32 байт после декодирования, хвостовые пробелы и `\n`
  срезаются; файл шире 0600 — отказ. Quadlet: `Secret=albums_master,type=mount,mode=0400,uid=<процесс>`.
  Ключи — `crypto/hkdf` SHA-256 с метками `pw/1`, `cookie/1`, `log/1` (**факт: пакет в stdlib**).
- `albums-svc -gen-secret`, `-gen-token` (32 байта, base64url, плюс строка `sha256` для конфига) —
  запускаются на машине владельца, не в юните (иначе вывод уйдёт в journald).
- **Смена секрета** (runbook): все пароли и входы негодны → владелец заново задаёт пароли через `PATCH`.

## 7. Журнал (001-18)

`log/slog`, JSON в stdout. Поля: `route` (шаблон), `status`, `code`, `bytes`, `ms`, `owner`, `album` —
8 hex `HMAC(k_log, id)`. Никогда: `Authorization`, токен и хэш, пароль, cookie, id, путь и строка запроса,
`title`, IP, тело. `store` возвращает ошибки без имени файла (операция, errno, `album`); свой `recover`
без пути. `TestLogNoSecrets` — полный прогон плюс отказ диска (только чтение, нет места) и паника в
обработчике.

Caddy: в журнале доступа путь `/a/*` заменён на `/a/…`, строка запроса отброшена, IP — маска /24 и /48;
то же в журнале ошибок (502 при остановленном сервисе пишет URI целиком). Срок хранения журналов —
требование этапа 4.

## 8. Бэкап и восстановление (требования; механизм — этап 4; 001-20)

- В копию входят `data/` целиком (страницы тоже) и конфиг; секрет — нет, только менеджер паролей владельца.
  Причина — в программе «Обновить по ссылке» есть только у изменённого альбома, у неизменённого
  дозагрузить нечем (**факт по коду программы, проверил оркестратор**); ≈ 24 МБ на альбом.
- Шифрование обязательно: `meta` содержит все id, а id — ключ доступа. Хранение ≤ 30 дней.
- `albums-svc verify -data <копия>` — только чтение (`store.OpenReadOnly`, без flock и записи): формат, `meta` ↔ путь, файлы `published` на месте.
- После восстановления — `albums-svc after-restore -data <dir>`, только при остановленном сервисе: берёт
  flock на `LOCK` (занят — отказ с кодом ≠ 0, иначе запись `meta` из памяти сервиса затёрла бы
  результат), `epoch++` у всех альбомов (снимок мог быть до `revoke_sessions` или смены пароля),
  `last_seen` ← now (иначе снимок месячной давности включит сторож часов). Альбом, удалённый между снимком и сбоем, вернётся до
  уборки по сроку — принятый риск (001-20).

## 11. Вопросы к контракту (сессии программы)

Ответ сессии программы 31.10: правок контракта сейчас не ждём (у программы пауза), решения — за владельцем
контракта; ниже — сведения для него, ни один пункт не блокирует 0.1.

- **К1.** `Validate` на превышение `pages` и `album_bytes` отдаёт `ValidationError` без признака предела,
  а OpenAPI обещает `413`; у клиента есть `albums.ErrLimit` (по `413`) — **факт, ответ программы**. Сервис
  считает страницы и сумму байт сам. Предложение на будущее: признак предела в `ValidationError`.
- **К2.** Кода «квота / мало места» нет; на `413` программа пишет «Сервис не принимает альбом такого
  размера» — `413 too_large` принят.
- **К4.** Программа пароль не обрезает и не нормализует (запрещены только Cc, Cf, Zl, Zp); сервис делает
  `TrimSpace` + NFC и при установке, и при проверке — расхождения нет. Цена: пароли, отличные лишь
  пробелами по краям, равны. Записать в контракт как поведение сервиса.
- **К5.** Экспорт программы пишет APP0 (JFIF), COM с меткой программы (всегда) и APP2 (ICC sRGB); Exif,
  XMP, IPTC — нет (**факт, ответ программы и `web_test.go`**). Сервис: белый список §4, COM разрешён, APP1,
  APP13 и прочие APPn — `400 bad_page`. Записать правило в OpenAPI для чужих клиентов.
- **К6.** Сервис 0.1 не принимает `image/webp` (`400 bad_manifest`, выключено конфигом), хотя тип есть в
  enum; признак принимаемых типов в `limits` — решения нет, оставляем.
- **К7.** Смена пароля у сервиса сбрасывает входы и без `revoke_sessions`; программа и так шлёт
  `RevokeSessions=true` — принято.
- Метка `api/albums/v0.1.0` — закрыто: есть с 29.10. К3 снят: `bad_page` в enum, белую страницу и номера
  вне 1…K проверяет `Conformance`.
