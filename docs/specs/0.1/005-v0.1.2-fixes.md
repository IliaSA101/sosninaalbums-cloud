# 005. Доправки v0.1.2: листалка, сайт студии, грабли первой раскатки

Статус: draft, редакция 3 — по повторным ревью и аудиту 07.11.2026.

Техрешение и `файл:строка` — [design.md](005-v0.1.2-fixes/design.md); развилки — [decisions.md](decisions.md),
«спека 005». API `/v1` не меняется (контракт — в программе, 0.32/146); предложения к контракту — в «Открытых вопросах».

## Зачем

v0.1.1 раскатан, первая выгрузка из программы прошла. Колесо мыши и свайп тачпада альбом не листают; фотографу нужна
ссылка на свой сайт. Первая раскатка показала грабли, которые стоят простоя, а одна — публичного адреса.

## Состав

| # | Что | Входит |
|---|---|---|

| 2 | Поле `site` владельца: конфиг, `view.json`, роль | да |

| 4 | Несколько доменов; ВМ в CI; быстрый просмотр листалки | нет — 005-14, 005-15, 005-1 |

альбомы фотографа.

## Поведение (сценарии)

1. **Колесо.** Щелчок вниз — вперёд, вверх — назад; колесо без паузы — одна страница до паузы.
2. **Тачпад Mac.** Двухпальцевый свайп влево/вверх — вперёд, вправо/вниз — назад; одна страница на жест, инерция не
   добавляет; браузер не уходит «назад по истории».
3. **Масштаб.** Щипок и Ctrl+колесо — масштаб браузера; при увеличенном виде два пальца двигают вид, а не листают.
4. **Телефон.** Без изменений.
5. **Сайт студии.** Задан `site` — подпись справа вверху ведёт на сайт в новой вкладке, сайт не узнаёт адрес альбома.
   Не задан или не прошёл проверку — текст. Форма входа и «не найдено» — без ссылок.
6. **«Исходный код».** Ссылки нет нигде; правило CSP web без исключений.
7. **Плохой `site` или неизвестный ключ владельца.** Роль отказывает до записи конфига (то же правило, что у сервиса —
   общий файл случаев); сервис тоже не стартует, сообщение без значения.
8. **`apply`.** Всегда через сохранённый план: план показан, проверен кодом, применяется ровно он. Сервер в state,
   привязки адреса нет, а план удаляет сервер (`--replace-server` или пересоздание) — отказ.
9. **`apply` упал после создания сервера.** `provision.sh hosts` пишет `hosts.yml` из state или по адресу с проверкой;
   `apply` печатает готовые команды ufw.
10. **`configure`.** LLMNR и mDNS выключены; в конце — проверка слушателей вне `lo` (как на стенде).
11. **Дымовая проверка** (`provision.sh smoke` на ops-ВМ, токен `smoke` из файла секретов; рабочая ВМ — только стенд):
    создать (срок 1 ч), загрузить, опубликовать, открыть, пароль, удалить; вывод без токена, id и ссылки; `clean` —
    остаток прошлого прогона. **Список** (`provision.sh albums`) — отдельным токеном фотографа, только `GET`.

## Требования

- Колесо: модуль `wheel.js` без DOM; доминирующая ось, порог, замок до тишины (старт 40 px, 450 мс), `deltaMode`;
  `ctrlKey` и `visualViewport.scale > 1` — пропуск без `preventDefault`; `document`, `passive: false`.
- `site`: необязательный; правило — design §1.1 (https, DNS-имя ASCII с буквенной последней меткой, без userinfo,
  запроса, якоря, порта, путь из безопасного набора, `u.String() == s`, ≤ 200 байт). Один файл случаев для сервиса,
  роли и листалки; листалка — ещё `URL()`, `https:` и `href` равен значению. В HTML сайт не подставляется.
- Ссылка — DOM, `rel="noopener noreferrer"`, `target="_blank"`, `referrerPolicy="no-referrer"`.
- `is_primary` убран; сверка state — `show -json` (обёртка tofu); новый shell — `deploy/ops/hosts.sh`, случаи CLI —
  `cli/inner_hosts.sh` (`provision.sh` и `inner.sh` — по 27 из 30 КБ).
- `hosts`: канонический десятичный IPv4, отказ для служебных диапазонов; одна проверка с `apply`; запись через
  временный файл, симлинк — отказ; в `main` — после просмотра кода, до секретов.
- Drop-in `resolved.conf.d/99-sa.conf` (побеждает последний файл) в роли `bootstrap`; самопроверка всех строк
  `Protocols:`; слушатели — в `post_tasks` `site.yml`.
- Дымовая проверка: `smoke.py` на стандартной библиотеке, в контейнере контроллера после просмотра кода; база — из
  `SA_DOMAIN`; токен — только файл ro; без редиректов; ошибки — шаг и класс; `upload` — на пустом списке.

## Модель угроз (новое)

| Угроза | Мера |
|---|---|
| XSS через `site` (`javascript:`, `data:`) | правило в роли и сервисе; листалка: `URL()`, `https:`, равенство `href`, только DOM |
| Расхождение Go и браузера (`https:/\h`, `127.1`, `0x7f.1`, `h:`) | печатный ASCII без `\`; последняя метка с буквы; без `:` в хосте; канонический вид |
| Роль мягче сервиса → сервис не стартует у всех | общий файл случаев; регэксп с `\Z`; неизвестные ключи, записи токенов — отказ роли |
| Открытый редирект | нет: ссылка из inventory, не из запроса |
| Адрес альбома (ключ) через Referer; tabnabbing | `noreferrer`, `referrerPolicy`, `<meta>`, заголовок; `noopener` |
| Потеря публичного адреса при удалении сервера | план проверяется кодом закрыто: удаление сервера без привязки в state — отказ |
| `hosts.yml` на чужой адрес (туда уйдёт пароль sudo) | канонический IPv4, служебные диапазоны — отказ, сверка с state, запись без симлинка; отпечаток ключа хоста |
| LLMNR/mDNS снаружи; новая служба на `0.0.0.0` | выключены; слушатели — в каждом `configure`; nftables — первый рубеж |
| Токен в `inspect`, `argv`, журнале; id в тексте исключения | только файл ro; вывод — шаг и класс исключения; тест по `podman inspect` |
| Дымовая проверка трогает альбомы фотографа | свой владелец `smoke`; `upload` — только на пустом списке; `DELETE` — только свой id; `clean` — только `smoke` |
| Токен списка — вторая копия прав фотографа | только ops-ВМ (файл секретов), отдельный токен; иначе не выпускать |
| Запасное имя в чужой зоне DNS (sslip.io) | только проверка раскатки: без клиентов и рабочего токена |

## Открытые вопросы

- **Владельцу («да»):** правка `scripts/check.sh` (задача П). Сейчас `engine.test.mjs` и `manifest.test.mjs` не
  запускает ни `check.sh`, ни CI.
- **Владельцу (операции, «да» на каждую):** первый бэкап и проверка восстановления — до пачки; `ss -Htulpn` на сервере
  до выпуска (сверка списка слушателей); восстановление привязки — сначала обычный `apply` без простоя, окно — только
  при отказе API (design §4.1); `--replace-server` — не проверено, что адрес сохраняется: только с «да» и снимком
  панели; токены `smoke`, `ops-ls` — выпуск на ops-ВМ в файл секретов; правило ufw ops-ВМ к серверу на 443; отзыв
  демо-токена после перехода; удаление тестовых альбомов временного имени (ссылки клиентам не уходили).
- **Сессии программы (через владельца):** `bytes` в элементе `GET /v1/albums` и `used`/`quota` владельца; после смены
  домена брать `url` из ответа, а не из сохранённой записи.
- **Гипотезы до приёмки** — помечены в design (пороги, Safari, повторная привязка, простой, DHCP-клиент в списке
  слушателей, DNS цели стенда, CA в образе контроллера).
