# 002. Подъём сервера с нуля: OpenTofu → Ansible

Статус: draft; **поправка 03.11.2026** — раскатка в отдельной ВМ (design §16, ВР-1…9).

Техрешение — [design.md](002-provisioning/design.md); факты и отвергнутое — [research.md](002-provisioning/research.md);
развилки — [decisions.md](decisions.md). Сервис, `data/`, конфиг и секрет — спека 001; артефакты — `deploy/`
(README). Решение по стеку и факты провайдера — см. приватные заметки.

## Зачем

Сервер поднимается и восстанавливается одной командой владельца: OpenTofu создаёт ресурсы у провайдера, Ansible
настраивает машину; руками — только DNS. Повтор безопасен. Аренды в этапе нет: всё проверяется локально в Podman.

## Поведение (сценарии)

Все команды `deploy/provision.sh` владелец запускает под `sa-ops` в **ВМ раскатки** без агентов
(ops-ВМ, design §16).

1. **Первый подъём.** `review.sh`: полный diff кода раскатки от прошлого развёртывания → «yes» → checkout;
   `provision.sh up`: второй взгляд → «yes» → фраза секретов → интерактивный `tofu apply`: ключ (импорт
   открытого), IPv4 с PTR, сервер «Debian 13», привязка IP → ожидание ssh → `bootstrap` под root или
   пользователем образа → `site.yml` под администратором → печать адреса. DNS — владелец.
2. **Повтор.** `provision.sh configure` — вход администратора есть → только `site.yml`; второй прогон `changed=0`.
3. **Правка.** Дайджест образа, токен фотографа → `configure` → перезапуск затронутых служб. Смена домена ломает
   выданные ссылки (001-22) — только переездом с переадресацией.
4. **Восстановление.** `provision.sh apply --replace-server` (привязка IP снимается до удаления сервера, IP
   остаётся) → `forget-host` → `configure` → возврат копии (этап 7, формат — design §11).
5. **Копия.** `provision.sh backup` забирает зашифрованный поток в каталог копий раскатки и проверяет метку
   конца, не расшифровывая на диск. Копии старше 30 дней удаляются; новейшая старше 7 дней — предупреждение
   (design §11).
6. **Краевые.** Код 3, без действий — на каждый отказ design §2 и §16.4: нет метки машины или жив
   `claude`/`node`; не та учётная запись или сессия; `CLAUDECODE`; дерево грязное, HEAD не отсоединён; токен или
   `TF_LOG*` в окружении. B/C или провайдер не `clo` → код 2. Сменился ключ хоста → отказ до `forget-host`.
   Вход и `sudo` администратора не проверены → root не закрывается. Нет метки конца копии → отказ, `.part`
   удаляется.

## Требования

- 0.1 — только способ A (`bootstrap`) и провайдер `clo`; B, C и другие провайдеры — задел без кода.
- **Граница доступа — отдельная ВМ** (design §16). Секреты, inventory и копии — только у `sa-ops` ops-ВМ без
  агентов, Claude и Node. Код — git bundle через общую папку VMware (у ops-ВМ только на чтение) с `fsck`; рубеж
  против агента один — полный diff `deploy/` от `deployed-commit` в `review.sh` до checkout; белый список
  символов; контроллер по ID. Метка машины и страж — от ошибки.
- **Секреты** — один файл, зашифрованный age по фразе, 0600 в доме раскатки: токен API, пароль vault, фразы
  ключей сервера и забора, ключ age копий. Расшифровывает контроллер по фразе каждый запуск, без кэша;
  дальше — каналы, токен — файл 0600 в `XDG_RUNTIME_DIR`, переменная `sensitive` + `ephemeral` (нет в
  state и плане). Ключи — ed25519 с фразой в своём `ssh-agent` на время прогона.
- `tfstate`, IP, домен, значения и секреты (`ansible-vault`) — в приватном inventory; в публичном — роли, шаблоны,
  пример с `example.org`.
- nftables `inet`, своя таблица, drop на **всех** интерфейсах; открыты tcp 22, 80, 443; правила — только
  `reload`. SSH — только ключ; root и пароль закрыты; администратор — отдельный, `sudo` по паролю (он же для
  консоли); подбор — `PerSourcePenalties`/`MaxStartups` sshd. Пользователь образа блокируется, затем удаляется.
- `albums` — без входа, rootless Podman, linger, subuid в 100000–524287 без пересечений; у администратора и
  пользователя бэкапа subuid нет; ACL на uid процесса для конфига; группа `albums` пуста.
- Caddy ровно 2.11.7 из apt-репозитория Caddy (ключ по отпечатку), конфиг — `deploy/caddy/Caddyfile` и
  `deploy/systemd/caddy-albums.conf`; исправления — правкой версии (design §8).
- unattended-upgrades — только безопасность Debian, перезагрузка ночью. `podman auto-update` — этап 7.
- `qemu-guest-agent` с белым списком команд; cloud-init не меняет пароли, ключи и пользователей (design §10).
- Бэкап: состав по 001-20, поток шифруется на сервере ключом age владельца, ключ забора — только
  `restrict,command=`; служба бэкапа видит только данные и конфиг; метка конца — только при успешном tar;
  хранение строго ≤ 30 дней; новейшая проверенная копия старше 7 дней — предупреждение. Возврат — разбор и
  распаковка от uid сервиса с пределом размера, без `NOPASSWD` (design §11).
- Второй прогон — `changed=0`. Образы проверок по дайджесту, в систему ничего не ставится.

## Модель угроз (новое)

Полностью — design §14, §16.

| Угроза | Мера |
|---|---|
| Секреты или подмена кода раскатки агентом рабочей ВМ | ВМ без агентов, буфера и SSH-сервера; файл секретов по фразе; fsck, полный diff до checkout; контроллер по ID |
| Канал bundle (подмена, ссылки) | одно имя, `nofollow`, предел, fsck во временном репозитории; у ops-ВМ `ro` |
| Раскатка в рабочей ВМ по ошибке | метка машины, процесс `claude`/`node`, страж |
| Кабинет провайдера = root (rescue, агент, cloud-init) | 2FA; агент без exec; модули cloud-init убраны; rescue и `bootcmd` — приняты |
| Окно root, самоблокировка | root закрывается после входа и `sudo -v` администратора; откат в обоих плеях |
| Удаление IP вместе с сервером | отдельная привязка |
| Порт наружу, локальная сеть | своя таблица nftables, `verify_listeners` |
| Подмена пакетов, образов, провайдера | lock + `SHA256SUMS`, ключ Caddy по отпечатку, дайджесты, pip с хэшами |
| Секрет в журнале, временных файлах | `--log-driver=none` у контейнеров с секретами; `no_log`, `pipelining`, `acl`; пути из tar — не в журнал |
| Кража ключа бэкапа, неполная копия | поток без аргументов, шифрован; метка последним членом |
| Вредный архив при возврате | разбор и распаковка от uid сервиса, только файлы и каталоги, предел размера |
| Caddy без исправлений | недельная проверка GHSA (runbook), этап 7 — Renovate |

## Критерии приёмки

Локально, в контейнерах, без сети провайдера (`deploy/tests/provision/run.sh <шаг>`, design §12):

- [ ] `tofu_fmt`, `tofu_validate`, `tofu_test` (`mock_provider`): `keypair_import_only`, `no_server_password`,
  `ip_attached_separately`; `tofu_static`: `ephemeral`, `prevent_destroy`, `ignore_changes`, нет `addresses`,
  провижинеров и `external`.
- [ ] `ansible_lint` (`offline`), `yamllint`, `syntax_check`, `shellcheck`, `selftest`, `ctl_shared`.
- [ ] `provision_cli`: код 2 на B/C; код 3 на каждый отказ design §2 и §16.4; метка из тестового файла
  секретов — не в argv, окружении контейнера, файлах и журнале (у `sa-prov-*` драйвер журнала `none`); `backup`
  без метки → `.part` удалён; копия старше 30 дней удалена, даже единственная; новейшая старше 7 дней → предупреждение.
- [ ] `converge_bootstrap` (через пользователя образа) → `converge_site` (без `albums-runtime`) → `idempotence`.
- [ ] Положительные проверки раньше отрицательных: `verify_ssh_admin_key`, `verify_admin_sudo`,
  `verify_sshd_effective`, затем `verify_ssh_*_denied` (root, пароль, чужой ключ, пользователь образа);
  `verify_nft_ports` (22, 80, 443 — да; 8080 — нет), `verify_nft_no_iface_exceptions`, `verify_nft_reload_only`, `verify_listeners`,
  `verify_users` (subuid; пользователь образа заблокирован, затем удалён), `verify_podman`, `verify_caddy`
  (2.11.7, `validate`, 80 → 308), `verify_upgrades`, `verify_journald`, `verify_guest_agent`, `verify_cloud_init`,
  `verify_backup_stream` (состав, метка, tar ≥ 2, журнал), `verify_restore_rejects` (симлинк, жёсткая ссылка,
  `..`, абсолютный путь, сверх предела).

В CI (rootful-цель; локально не хватает subuid — research §2):

- [ ] `converge_full` с `albums-runtime`, `verify_acl`, `/v1/health` через сокет от имени `caddy`,
  `idempotence_full`, `verify_after_restart`; `verify_backup_stream` в полном режиме (`SA_STAND_FULL=1`).

На пробной аренде (design §13): настоящие `apply`; PTR; один внешний адрес; `--replace-server` оставляет IP;
первый вход; cloud-init и сеть; консоль, rescue; скан; агент; сертификат; ночная перезагрузка; повторный `up` —
`changed=0`; время забора копии.

## Не входит

- Способы B, C; провайдеры кроме `clo`; restic, S3, расписание забора, плей возврата копии и учение — этап 7.
- `podman auto-update`, Renovate, смоук после деплоя, отчёт — этап 7. Регистрация, аренда, DNS — владелец.
